## 3. Принятые решения (обязательны к исполнению)

| № | Решение |
|---|---|
| Р1 | **Заявки принимаются только на сайте.** `/apply` — брендированная посадочная страница с формой-карточкой и пошаговым мастером. Внешние формы не используются. |
| Р2 | **Оператор ПДн — Ассоциация** (Межрегиональная общественная организация выпускников СГЮА «Ассоциация выпускников СЮИ – СГАП – СГЮА»). ООО «АСПБ» — обработчик по поручению (ч. 3 ст. 6 152-ФЗ). |
| Р3 | **Срок обработки ПДн — до 31.12.2030** (по формам Приложений № 10–12). |
| Р4 | **Согласия — электронные** (отдельные чекбоксы, фиксация даты, времени, сетевого адреса и версии текста). Бланки PDF/DOCX формируются для скачивания, загружать их не нужно. |
| Р5 | **Исключение — несовершеннолетние:** согласие законного представителя (Приложение № 11) требует **и галочки, и скана** подписанного бланка. Без скана заявка не уходит в техническую проверку. |
| Р6 | **Состав заявки — по Приложению № 1**, оценочный лист — по Приложению № 9 (балл + обоснование + рекомендации). |
| Р7 | **Отправка писем не реализуется.** Письма не должны быть условием ни одного сценария. Доступ в кабинет выдаётся ссылкой на экране и через админку. Таблица `notifications_outbox` создаётся заранее. |
| Р8 | **Число финалистов — от 10.** Группы по 3 команды; при числе, не кратном трём, состав определяет Оргкомитет. |
| Р9 | **В подвале сайта — только Ассоциация выпускников.** СГЮА исключена из документов конкурса; блок «СОГЛАСОВАНО» из шапки Положения удалён. |
| Р10 | **Новый блок «Архив законопроектов»** — публичный раздел `/initiatives` (пакет 5 и ТЗ `02-domain-competition.md`, п. 14; `04-database.md`, п. 10). |
| Р11 | Дедлайны проверяются только на сервере по МСК (UTC+3), окончание — 23:59:59 последнего дня. |
| Р12 | Итоговый балл — среднее арифметическое сумм членов комиссии, округление до сотых; расхождение > 20 баллов → дополнительная оценка председателя (п. 7.7). |
| Р13 | Никаких связей с проектом «ТехнологИИ Права»: гейты Г1–Г7 проходят на каждом коммите. |
| Р14 | Секреты только в окружении. ПДн, `.env`, дампы, `node_modules` в репозиторий не попадают. |
| Р15 | Документы Положения и Приложений **уже отредактированы** — переписывать их не нужно. |

## 4. Чего делать нельзя

1. Подключать внешние формы, зарубежные облака и сервисы рассылок.
2. Хранить ПДн вне БД на территории РФ; отправлять данные участников в мессенджеры.
3. Публиковать материалы команд, оценки, рейтинги, ПДн и архивные инициативы без согласий.
4. Ослаблять проверки дедлайнов, ролей и принадлежности команды.
5. Тащить доменный код донора: `manyasha`, `webinar`, `conference`, `speaker`, `yookassa`, `yandex-pay`, `academy`, `slot` (гейт Г2).
6. Переписывать историю git, делать force push, коммитить в `main`.
7. Выполнять на проде необратимые операции без дампа и слепка (раздел 6).
8. Додумывать требования: неясность → вопрос владельцу.

### 6.2. Предохранители — обязательны перед каждым изменением прода

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
mkdir -p /root/lideryprava-snapshots/$STAMP
sqlite3 /var/www/lideryprava/data/applications.db ".backup /root/lideryprava-snapshots/$STAMP/applications.db"
tar czf /root/lideryprava-snapshots/$STAMP/www.tgz -C /var/www lideryprava
cp /etc/nginx/sites-available/lideryprava /root/lideryprava-snapshots/$STAMP/nginx.conf
systemctl cat lideryprava > /root/lideryprava-snapshots/$STAMP/lideryprava.service
sha256sum /var/www/lideryprava/*.html /var/www/lideryprava/robots.txt > /root/lideryprava-snapshots/$STAMP/public.sha256
```

Без этого шага к изменениям не приступать. Путь к слепку фиксировать в отчёте.

### 6.3. Порядок выката (без простоя)

1. **БД.** Установить PostgreSQL, создать пользователя `liders` и БД `liders`; прогнать `npm run migrate`. Старую SQLite **не трогать**.
2. **API.** Развернуть в `/var/www/lideryprava-api` (`tsc` → `dist/`), секреты — в `/etc/lideryprava/api.env` с правами `600`, юнит `liders-api` из `ops/systemd/liders-api.service` на `127.0.0.1:8091`. Старый `server.py` продолжает работать.
3. **Проверка API.** `curl -s http://127.0.0.1:8091/api/health` → `{"status":"ok","database":"up"}`.
4. **Фронтенд.** Собрать публичную часть и админку, положить в `/var/www/lideryprava/public` и `/var/www/lideryprava/admin`. Публичный сайт пока старый.
5. **Переключение nginx** по `ops/nginx/lideryprava-platform.conf` в согласованное окно: `nginx -t && systemctl reload nginx`. Прежний конфиг — в слепке.
6. **Проверки после переключения** (результаты — в отчёт):
   ```bash
   for p in / /about /stages /initiatives /masterclasses /winners /documents /contacts /apply \
            /legal/offer /legal/privacy /robots.txt /sitemap.xml /favicon.ico; do
     printf '%-22s %s\n' "$p" "$(curl -s -o /dev/null -w '%{http_code}' https://lideryprava.ru$p)"; done
   curl -s https://lideryprava.ru/api/health
   curl -s -o /dev/null -w '%{http_code}\n' https://lideryprava.ru/this-path-does-not-exist   # 404
   curl -s -o /dev/null -w '%{http_code}\n' https://lideryprava.ru/data/applications.db      # 404
   ```
7. **Перенос истории.** Заявки сезона 2026 из SQLite → `legacy_applications` (только чтение в админке).
8. **Наблюдение 72 часа:** `journalctl -u liders-api`, `error_log` nginx, доступность, тестовая подача заявки.

### 6.4. Откат

```bash
cp /root/lideryprava-snapshots/$STAMP/nginx.conf /etc/nginx/sites-available/lideryprava
nginx -t && systemctl reload nginx
systemctl stop liders-api
systemctl start lideryprava
```

Данные, поданные через новую платформу до отката, сохраняются в PostgreSQL и переносятся повторно после исправления — терять заявки нельзя.

### 6.5. Чего на проде не делать

1. Не удалять старый сайт, `server.py`, SQLite и старые конфиги — минимум 30 дней после стабильной работы.
2. Не менять `robots.txt` на `Disallow: /`.
3. Не выполнять `DROP DATABASE`, `rm -rf` по каталогам сайта, не перезаписывать `/etc/nginx` без бэкапа.
4. Не трогать таймеры бэкапов и TLS.
5. Не публиковать и не пересылать содержимое `applications.db` — там персональные данные.

> Отдельные работы по инциденту с публичным доступом к `/data/applications.db` владелец **отложил** — специально их не выполняй. Целевой конфиг nginx служебные пути уже запрещает, поэтому после переключения доступ закроется сам.

### Пакет 1. Схема БД (миграции `011`+)

## 9. Известные ловушки

1. `npm install` может падать с `EPERM` на общем кэше — используй `--cache /tmp/liders-npm-cache`.
2. Пользователь PostgreSQL `pravo` может не иметь права `CREATEDB`.
3. CRUD админки принимает имена полей **как в БД** (`recording_url`, `sort_order`), не camelCase.
4. «Прошедший мастер-класс только с записью» проверяется и при создании, и при изменении (валидация получает объединённое состояние записи).
5. `search_path` выставляется на каждом соединении; таблиц в `public` быть не должно.
6. Фоновых заданий в `app.listen` нет — расписание отдельными процессами.
7. Старый сайт отдаёт `200` на любой путь (soft-404) — новая платформа обязана отдавать `404`.
8. Не переноси приложение `apps/techforum` и прототипы донора — у них свои БД.

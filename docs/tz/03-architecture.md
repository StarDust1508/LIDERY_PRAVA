# 03. Архитектура и разделение с «ТехнологИИ Права»

## 1. Стек

| Слой | Решение | Почему |
|---|---|---|
| Сервер | Node.js 20+, Express 4, TypeScript (ESM) | Совпадает с донором, переносится проверенный код |
| БД | PostgreSQL 15+ | Донор использует Postgres; нужны JSONB, транзакции, полнотекстовый поиск |
| Драйвер | `pg` напрямую, без ORM | В доноре нет ORM; меньше магии, предсказуемые SQL-миграции |
| Миграции | Собственный раннер (файлы `.sql` + таблица `_migrations` + advisory-lock) | Проверенный паттерн донора, без лишних зависимостей |
| Файлы | Таблица `media` (BYTEA) + проверка MIME и magic-байтов | Файлы конкурсных материалов небольшие; один механизм вместо четырёх |
| Большие видео | Хранение записей мастер-классов — **внешняя ссылка** (ВК/Яндекс.Диск РФ-юрлица) | П. 14.4 Положения; экономия диска |
| Админ-аутентификация | Stateless HMAC-токен + таблица отзыва сессий | Переносится из донора как есть |
| Публичный фронтенд | React 18 + Vite + TypeScript + Tailwind (из донора) | Дизайн меняется, но стек сохраняется |
| Админка | Отдельная сборка на том же стеке | Требование владельца: админка — независимая часть |
| Деплой | nginx + systemd + отдельная БД `liders` | Совпадает с текущей инфраструктурой `lideryprava.ru` |

Запрещено добавлять без отдельного решения: ORM, Redis, очередь, Kubernetes, микросервисы, GraphQL, внешние SaaS для ПДн.

## 2. Границы разделения

Разделение обязательно подтверждается проверками (п. 6). Целевое состояние — **0 доменных зависимостей**; допустимая связь с донором — только архитектурный паттерн, зафиксированный в этом ТЗ.

### 2.1. Переносится (ядро)

| Блок донора | Что берём | Что меняем |
|---|---|---|
| `server/src/config.ts` | Проверка обязательных env, типизация конфига | Убрать дефолты `tech-pravo.ru`, `bankruptcy_academy`, `ba_app`, `pravo` |
| `server/src/db.ts` | Пул, `search_path` | Схема `liders` вместо `pravo`+`public` |
| `server/src/migrate.ts` | Раннер миграций с advisory-lock | Оставить, добавить проверку целостности нумерации |
| `server/src/middleware/security-headers.ts` | CSP и заголовки | Свой список источников |
| `server/src/middleware/rate-limit.ts` | In-memory лимитер | Без изменений |
| `server/src/routes/auth.ts` | HMAC-токен админ-сессии, отзыв сессий | Убрать доменные роли |
| `server/src/routes/media.ts` | Загрузка/выдача файлов, whitelist, magic-байты | **Удалить доменный SQL** к `research_assets`/`research_reports` (в доноре стр. ~76–94) |
| `server/src/routes/leads.ts` + `lib/leads.ts` | Приём обращений | Разделить: приём — ядро, QR/партнёрка/QA — удалить |
| `server/src/routes/settings.ts` | Настройки + ревизии | Убрать импорты `bfl-practicum`, `landing-workspace`, `manyasha-research` и 22 доменных префикса |
| `seo.ts` | Механизм мета-тегов, sitemap | Полностью переписать контент под `lideryprava.ru` |
| `analytics.ts` | Механизм счётчиков | Убрать реальные GSC/Яндекс-verification донора |
| Инфраструктурные скрипты | nginx/systemd/deploy-паттерн | Адаптировать под текущий прод `lideryprava.ru` |

### 2.2. Не переносится (домен «ТехнологИИ Права»)

Конференция и спикеры, билеты и check-in, платежи (Яндекс.Пэй, ЮKassa, банковские выписки), вебинары и HLS, академия и курсы, исследования, digital-продукты и подписки, партнёрская программа и реферальные ссылки, «Маняша» и любые ИИ-контуры, слоты и розыгрыши, обязательства, QA-стенд, CMS мобильного приложения, Telegram-бот, `/internal/*`-эндпоинты, приложение `apps/techforum` (у него своя БД `techforum` и свои миграции в `apps/techforum/drizzle/`), прототип `apps/manyasha-stage`.

Ориентир по объёму: в доноре ≈228 таблиц и 195 файлов миграций; после выделения ядра остаётся **порядка 20–25 таблиц**, к которым добавляются таблицы конкурса (раздел 04).

### 2.3. Требует решения при переносе

| Вопрос | Решение по умолчанию |
|---|---|
| Пользовательская аутентификация (JWT `requireUser`) | **Оставить**: нужны админы и операторы; участники входят по токену команды, без паролей |
| Хранение файлов BYTEA | Оставить для материалов до 25 МБ; видео — ссылкой |
| Генерация PDF/DOCX на сервере | Оставить только `pdfkit` (сертификаты участников, PDF Положения — статикой) |
| Почта | Транспорт — UniSender через HTTP (как в доноре) или `nodemailer`; решить на этапе 05. В доноре `nodemailer` объявлен, но не используется — мёртвую зависимость не тащить |
| Схема для `_migrations` | Та же `liders` |

## 3. Структура репозитория (целевая)

```
LIDERY_PRAVA/
├── docs/tz/                     # это ТЗ
├── platform/                    # новая платформа
│   ├── server/                  # Express + TS
│   │   ├── src/
│   │   │   ├── config.ts
│   │   │   ├── db.ts
│   │   │   ├── migrate.ts
│   │   │   ├── index.ts
│   │   │   ├── middleware/      # security-headers, rate-limit, require-admin, require-team
│   │   │   ├── routes/          # public, cabinet, admin
│   │   │   └── lib/            # mailer, deadlines, scoring, storage
│   │   ├── package.json
│   │   └── .env.example
│   ├── migrations/              # 001_…, 002_… — только схема liders
│   └── admin/                   # сборка админ-панели (отдельное задание, 07)
├── ops/                         # nginx, systemd, deploy, backup
└── README.md
```

Текущее содержимое ветки `main` (статический сайт и `server.py`) на этой ветке **остаётся на месте, в корне, и не изменяется**: это рабочая точка отката. Перенос файлов в `legacy-site/` выполняется отдельным коммитом в момент выката (раздел 10), чтобы переход был обратимым. Файлы, обязанные отдаваться по фиксированным путям (`mailru-domain*.html`, `robots.txt`, `favicon.ico`, `site.webmanifest`), сохраняют свои адреса навсегда.

## 4. Окружения

| Окружение | Домен | БД | Назначение |
|---|---|---|---|
| Локальное | `localhost` | `liders_dev` | Разработка, миграции с нуля |
| Тестовое | `stage.lideryprava.ru` (или подкаталог за паролем) | `liders_stage` | Приёмка, демонстрация Оргкомитету |
| Продуктивное | `lideryprava.ru` | `liders` | Рабочий конкурс |

Правила:
1. Тестовое и продуктивное окружения — **разные БД и разные каталоги файлов**.
2. Перенос данных из тестового в продуктивное запрещён; продуктив наполняется из форм и админки.
3. Секреты окружений не пересекаются: у каждого свои `JWT_SECRET`, `ADMIN_SESSION_SECRET`, пароль БД.

## 5. Принципы архитектуры

1. **Тонкие роутеры, толстые библиотеки.** Логика — в `lib/`, роутер только валидирует вход и формирует ответ.
2. **Один способ делать вещь.** Одна загрузка файлов, одна отправка письма, один расчёт баллов.
3. **Никаких фоновых заданий при старте.** Напоминания и рассылки — по явному расписанию (cron/systemd timer), с журналом. В доноре 12 заданий стартуют в `app.listen`, а `uncaughtException` не завершает процесс — это источник тихих ошибок; повторять нельзя.
4. **Никаких скрытых монтирований.** Все роутеры подключаются в одном месте (`index.ts`); запрещены `install*()` внутри других роутеров (в доноре так спрятаны 7 модулей).
5. **Идемпотентность приёмных эндпоинтов.** Повторная отправка формы не создаёт дубль (ключ идемпотентности).
6. **Каждое изменение данных — с автором и временем.** Журнал действий (`audit_log`) для всех админских операций.
7. **ПДн отделены от публичных данных** физически: таблицы участников не имеют публичных выборок, ни один публичный эндпоинт не возвращает ПДн (раздел 11).

## 6. Гейты разделения (обязательны в CI)

Выполняются на каждый push; падение гейта блокирует слияние.

| № | Проверка | Команда | Ожидание |
|---|---|---|---|
| Г1 | Нет упоминаний донора | `grep -rniE "tech-pravo\|pravotech\|expertum\|NeuroPravo\|TechPravoAI" platform/` | 0 совпадений |
| Г2 | Нет доменных сущностей | `grep -rniE "manyasha\|webinar\|conference\|speaker\|yookassa\|yandex-pay\|academy\|slot" platform/server/src platform/migrations` | 0 совпадений |
| Г3 | Нет чужих дефолтов БД | `grep -rniE "bankruptcy_academy\|ba_app\|search_path.*pravo" platform/` | 0 совпадений |
| Г4 | Нет мёртвых зависимостей | `npm ls --omit=dev` в `platform/server` | Список строго из раздела 1 |
| Г5 | Одна схема | `grep -rn "CREATE TABLE" platform/migrations \| grep -v "liders\."` | 0 совпадений |
| Г6 | Нет импортов вне ядра | Проверка, что каждый файл `routes/` импортируется в `index.ts` | 100 % покрытие |
| Г7 | Типы | `npx tsc --noEmit` в `platform/server` и в корне | Ошибок нет |
| Г8 | Миграции применяются с нуля | Развёртывание пустой БД и `npm run migrate` | Успех без ручных правок |

Гейты Г1–Г3 проверяются скриптом `platform/scripts/check-decoupling.sh`, который запускается и локально, и в CI.

## 7. Что считается нарушением разделения

1. Прямой импорт файла из проекта-донора по абсолютному пути.
2. Проверка `if (project === 'lidery')` или любой подобный флаг совместного использования.
3. Общая БД или общая таблица с `tech-pravo.ru`.
4. Общая админка, обслуживающая два домена из одной сборки.
5. Ссылка на домены, бренды, telegram-ботов и почту донора в коде, письмах, мета-тегах и документах.
6. Заимствование доменного SQL из `media.ts` и `settings.ts` донора без удаления (см. 2.1).

Допустимое «наследование» — только архитектурные решения: структура миграций, схема админ-сессии, подход к загрузке файлов, порядок middleware.

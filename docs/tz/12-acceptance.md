# 12. Приёмка, Definition of Done и тесты

## 1. Definition of Done

### 1.1. Общие требования к любой задаче

1. Требование выполнено буквально, а не «похоже».
2. Есть способ проверки, и он назван (команда, сценарий, тест).
3. Типы собираются без ошибок (`tsc --noEmit`), сборка проходит.
4. Гейты разделения (раздел 03, п. 6) проходят.
5. Нет секретов, реальных ПДн и мусорных файлов в коммите.
6. Формулировки интерфейса соответствуют словарю терминов (раздел 02, п. 12).
7. Изменения описаны в коммите по-русски: что и зачем.

### 1.2. Бэкенд и БД

1. Миграции применяются на пустой БД без ручных правок; повторный запуск не ломает схему.
2. Каждое ограничение из раздела 04 реализовано в БД или проверено на сервере (и то и другое — для критичных).
3. Дедлайны проверяются на сервере по МСК; обход через прямой запрос невозможен.
4. Расчёт баллов и рейтинга покрыт тестами: среднее, округление до сотых, расхождение > 20 баллов, равенство мест.
5. Ни один публичный эндпоинт не возвращает ПДн (проверяется тестом).
6. Rate-limit и идемпотентность проверены.

### 1.3. Личный кабинет

1. Вход по токену, повторное использование старой ссылки невозможно.
2. Команда не может обратиться к чужой команде (проверено тестом).
3. После дедлайна изменение материалов запрещено сервером, интерфейс объясняет причину и показывает контакты.
4. Загрузка файла, замена, удаление до дедлайна — работают; лимиты и типы проверяются.
5. Все состояния проработаны: пустой комплект, замечания, отказ, выход в следующий этап.

### 1.4. Админ-панель

1. Роли `admin` и `operator` различаются фактически, а не в интерфейсе.
2. Опасные действия требуют подтверждения и попадают в журнал.
3. Экспорт учитывает фильтры и не содержит технических ПДн.
4. Публикация протокола и запуск срока апелляций работают связно.

### 1.5. Публичная часть

1. Все маршруты из карты (раздел 08, п. 2) отвечают корректными кодами.
2. Несуществующий путь отдаёт `404`.
3. Навигация работает с клавиатуры и на мобильных.
4. Нет ошибок в названиях разделов и «ИИшных» формулировок (проверяется вычиткой).
5. `canonical`, `description`, OG-теги присутствуют на всех индексируемых страницах.
6. Мастер-классы: прошедший без записи не публикуется.

### 1.6. Юридические документы

1. Все документы — от имени Ассоциации, с версией и датой редакции.
2. Реквизиты заполнены (после получения от Ассоциации).
3. PDF Положения доступен и совпадает по тексту с документом.
4. Акцепт фиксируется с версией документа и временем.

## 3. Тестовая матрица

| Область | Обязательные тесты |
|---|---|
| Валидация | Возраст, численность 2–4, уникальность участника, два наставника максимум, набор согласий |
| Дедлайны | Границы: за секунду до и после срока; смена даты сезона; замечание с 2 рабочими днями |
| Расчёты | Среднее, округление до сотых, расхождение > 20, сумма дебатов, равенство мест и приоритеты |
| Доступ | Публичный / команда / эксперт / оператор / админ — по каждому эндпоинту |
| Файлы | Тип, размер, magic-байты, имя с кириллицей и пробелами, скачивание |
| Импорт | Архив заявок (CSV/XLSX): корректные строки, дубли, пустые поля, предпросмотр |
| Редиректы | Все старые URL из sitemap и из внешних ссылок |
| 404 | Случайные пути, вложенные несуществующие пути |
| Письма | Создание заявки, замечание, публикация протокола, напоминания — доставка и текст |
| Формы | Ошибки рядом с полем, сохранение введённого при ошибке |

## 4. Регрессионные проверки перед выкатом

1. 14 публичных маршрутов отвечают `200`.
2. Вход в админку, список заявок, карточка, экспорт — работают.
3. Кабинет: вход по токену, загрузка, дедлайн.
4. Миграции на пустой БД.
5. Бэкап создан, восстановление проверено.
6. Гейты разделения пройдены.
7. Юридические страницы открываются, PDF Положения доступен.

## 5. Критерии подписания приёмки

1. Все сценарии С1–С8 пройдены без блокирующих дефектов.
2. Блокирующие дефекты: недоступность приёма заявок, потеря данных, нарушение прав доступа, публикация ПДн, ошибки в названиях разделов и юридических документах.
3. Некритические дефекты оформлены списком с оценкой и сроком устранения.
4. Приёмку подписывают: представитель Оргкомитета и ответственный за ПДн (в части документов и согласий).

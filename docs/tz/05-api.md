# 05. Контракты API

Все эндпоинты — под префиксом `/api`, JSON в UTF-8, время в ISO 8601 с зоной (`2026-11-11T00:00:00+03:00`).

## 1. Общие правила

1. **Формат ответа.** Успех: `{ "data": … }`; список дополнительно `{ "data": […], "meta": { "total": n, "page": p, "perPage": 50 } }`. Ошибка: `{ "error": { "code": "…", "message": "…", "details": {…} } }`.
2. **Коды ошибок.** `validation_failed` (422), `unauthorized` (401), `forbidden` (403), `not_found` (404), `deadline_passed` (409), `conflict` (409), `rate_limited` (429), `payload_too_large` (413), `internal_error` (500).
3. **Сообщения пользователю — по-русски и по делу.** «Срок приёма материалов отборочного этапа истёк 11 декабря 2026 года» вместо «Deadline passed».
4. **Пагинация.** `?page=1&perPage=50`, максимум `perPage=200`.
5. **Идемпотентность.** Приёмные эндпоинты (`POST /api/applications`, `POST /api/leads`, `POST /api/cabinet/materials`) принимают заголовок `Idempotency-Key`; повтор с тем же ключом возвращает прежний результат и не создаёт дубль.
6. **Лимиты.** Публичные приёмные эндпоинты: 10 запросов в минуту с IP; вход в админку: 8 в минуту с IP; вход в кабинет по токену: 10 в минуту с IP.
7. **Транспорт.** Только HTTPS. Cookie сессий — `HttpOnly`, `Secure`, `SameSite=Lax`.
8. **Никаких ПДн в GET-параметрах** и в логах (кроме усечённого IP в журнале безопасности).
9. **Валидация на сервере.** Клиентская валидация не считается защитой.

## 2. Аутентификация

| Контур | Механизм | Cookie/заголовок |
|---|---|---|
| Админ | HMAC-токен `v3.payload.signature`, ключ `ADMIN_SESSION_SECRET` (не короче 32 символов), отзыв через `admin_session_revocations` | Cookie `liders_admin_session`, 12 часов |
| Кабинет команды | Токен доступа команды (случайные 32 байта, в БД только SHA-256), обмен на сессионную cookie | Cookie `liders_team_session`, 7 дней |
| Публичный | Без аутентификации | — |

Правила:
1. Пароли админов — `bcrypt` (cost ≥ 12). Пароль из переменной окружения используется только для первичного входа/восстановления.
2. Роли: `admin` (всё), `operator` (заявки, материалы, обращения, мастер-классы; без управления пользователями, настройками, экспертами и публикации протоколов).
3. Токен команды выдаётся: (а) автоматически по факту регистрации заявки, (б) вручную админом, (в) повторно по обращению; при повторной выдаче старый отзывается.
4. Все попытки входа пишутся в `auth_log` (успех и отказ).

| GET | `/api/masterclasses` | Мастер-классы: `?status=announced\|past`; для `past` обязательна запись |
| GET | `/api/news` | Новости и видео: `?type=news\|video&page=` |
| GET | `/api/news/:slug` | Материал целиком |
| GET | `/api/documents` | Юридические документы и Положение (PDF) |
| GET | `/api/winners` | Победители по годам: `?year=2025` |
| GET | `/api/pages/:slug` | Статические страницы («О конкурсе», «История конкурса») |

Публичный эндпоинт **не возвращает** ПДн участников, материалы команд, оценки и рейтинги до `rankings.is_published = true`.

### 3.1. `POST /api/leads`

```json
{
  "name": "Иванов Иван Иванович",
  "email": "ivan@example.ru",
  "phone": "+7 900 000-00-00",
  "topic": "question",
  "message": "…",
  "consentPdn": true,
  "source": "public_form"
}
```
Ответ `201`: `{ "data": { "id": 123, "status": "new" } }`. Обязательны `name`, `contact` (email или телефон), `message`, `consentPdn`. Письмо-уведомление — в `notifications_outbox`.

### 3.2. `POST /api/applications` (форма сайта, если включена)

Тело — `multipart/form-data` (файлы) или JSON (ссылки). Состав:
`seasonId`, `directionId`, `team{name}`, `participants[]`, `mentors[]`, `materials[]`, `consents{}`, `captcha`.

Проверки при приёме:
1. Приём заявок открыт (`applications_open_at ≤ now ≤ applications_close_at`, время МСК).
2. Возраст каждого участника 16–35 лет включительно на дату закрытия приёма.
3. Численность 2–4 (или единоличное участие с подтверждением Оргкомитета).
4. Уникальность участника в сезоне по `person_key`.
5. Обязательные согласия: ПДн — у всех; распространение — по желанию; законный представитель — для лиц младше 18.
6. Комплект материалов отборочного этапа по `material_requirements`.
7. Ссылки — только российские домены (белый список).

Ответ `201`: `{ "data": { "applicationId": 45, "teamToken": "…", "cabinetUrl": "https://lideryprava.ru/cabinet/access?token=…" } }`. Токен показывается один раз и одновременно уходит письмом капитану.

## 4. Личный кабинет команды

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/cabinet/access` | Вход по токену: `{ token }` → сессионная cookie |
| POST | `/api/cabinet/logout` | Выход |
| GET | `/api/cabinet/overview` | Сводка: команда, статус заявки, дедлайны, что осталось догрузить |
| GET | `/api/cabinet/team` | Данные команды, участников, наставников |
| PATCH | `/api/cabinet/team` | Изменение названия команды, направления (до блокировки содержания) |
| POST | `/api/cabinet/participants` | Добавить участника (проверка численности и уникальности) |
| PATCH | `/api/cabinet/participants/:id` | Изменить данные участника |
| DELETE | `/api/cabinet/participants/:id` | Удалить участника (до публикации итогов отборочного этапа, с проверкой «не менее половины состава») |
| POST/PATCH/DELETE | `/api/cabinet/mentors[/:id]` | Наставники, не более двух |
| GET | `/api/cabinet/materials` | Комплект материалов: тип, статус, замечания, срок досдачи |
| POST | `/api/cabinet/materials` | Загрузить файл (multipart) или передать ссылку `{ type, externalUrl }` |
| DELETE | `/api/cabinet/materials/:id` | Удалить материал до дедлайна |
| GET | `/api/cabinet/deadlines` | Дедлайны этапа с пояснениями |
| POST | `/api/cabinet/contact-organizers` | «Связаться с организаторами» → создаёт `leads` |
| POST | `/api/cabinet/withdraw` | Отказ от участия (п. 4.10 Положения) с подтверждением |
| POST | `/api/cabinet/final-confirmation` | Подтверждение участия в финале, состав выступающих, презентация |

Правила:
1. Все эндпоинты кабинета требуют сессию команды и работают **только со своей командой**; обращение к чужому `id` — `403`.
2. Загрузка после дедлайна запрещена (`409 deadline_passed`); вместо неё интерфейс предлагает «Связаться с организаторами».
3. Изменение содержания материалов после окончания приёма заявок запрещено (`is_content_locked`); разрешена только досдача недостающих документов по замечанию Оргкомитета в пределах `fix_deadline_at`.
4. Изменение состава допускается однократно и не позднее публикации итогов отборочного этапа; включение новых участников на финальном этапе запрещено (п. 4.5).
5. Каждое изменение состава и материалов пишется в `audit_log` с указанием, что действие выполнено командой.

| GET/POST/DELETE | `/api/admin/media[/:id]` | Файлы |

Правила:
1. Все эндпоинты `/api/admin/*`, кроме `login`, требуют роль; `operator` не имеет доступа к `users`, `settings`, `experts`, `rankings/publish`, `export/*`.
2. Массовые операции (смена статуса, публикация, рассылка) выполняются только с предпросмотром и записью в `audit_log`.
3. Публикация протокола необратима без явного «снять с публикации» (тоже журналируется).
4. Экспорт ПДн — отдельное право, фиксируется в журнале (кто, когда, что выгрузил).

## 6. Обработка ошибок и наблюдаемость

1. Каждый ответ об ошибке содержит `requestId`; тот же `requestId` пишется в журнал сервера.
2. `GET /api/health` отдаёт состояние БД и версию сборки; используется внешним мониторингом.
3. Медленные запросы (> 1 с) и ошибки 5xx пишутся в журнал с путём и `requestId`.
4. Персональные данные в журналы не попадают: логируются идентификаторы, а не значения.

# 07. Админ-панель (отдельное задание)

Админ-панель — самостоятельная часть проекта со своей сборкой, маршрутом `/admin` и правами. Она создаётся на базе каркаса админки `tech-pravo.ru` (проверенная схема входа и раскладка), но наполняется **только** разделами конкурса.

## 1. Общие требования

1. **Маршрут:** `/admin`, отдельная сборка, не пересекается с публичным бандлом.
2. **Вход:** e-mail + пароль, сессия 12 часов, автоматический выход при бездействии 60 минут, кнопка «Завершить все сеансы».
3. **Роли:**
   - `admin` — всё, включая пользователей, настройки, экспертов и публикацию протоколов;
   - `operator` — заявки, материалы, обращения, мастер-классы, новости, документы; без управления пользователями, настройками, экспертами и без публикации протоколов.
4. **Раскладка:** постоянное левое меню, хлебные крошки, заголовок раздела, панель действий справа; таблицы с фильтрами, сортировкой и постранично по 50 записей.
5. **Каждое действие обратимо или подтверждается.** Удаление, отклонение, публикация и рассылка — только через диалог подтверждения с указанием последствий.
6. **Пустые состояния и ошибки** формулируются по-русски и подсказывают следующее действие («Заявок пока нет. Они появятся здесь после первой подачи через форму»).
7. **Счётчики внимания:** в меню отображается число необработанных заявок, материалов с замечаниями, апелляций в сроке, обращений без ответа. Счётчик ведёт в отфильтрованный список.
8. **Экспорт** любой таблицы в CSV/XLSX с учётом текущих фильтров; выгрузка ПДн — отдельное право и запись в журнале.

## 2. Разделы админки

### 2.1. Сводка (`/admin`)

Ключевые показатели сезона: число заявок по статусам, комплектность материалов, число команд по этапам, ближайшие дедлайны, очередь апелляций, последние действия администраторов. Никаких декоративных графиков «для красоты» — только то, что требует решения.

### 2.2. Заявки (`/admin/applications`)

| Колонка | Содержание |
|---|---|
| № | Идентификатор заявки |
| Команда | Название, направление |
| Капитан | ФИО, контакт |
| Участников | 2–4 (или «единолично, согласовано») |
| Источник | форма сайта; `archive` — для импортированных исторических заявок |
| Подана | Дата и время (МСК) |
| Проверка | Статус технической проверки |
| Комплект | «7 из 7» / «5 из 7» |
| Действия | Открыть, принять, вернуть с замечанием, отклонить |

Фильтры: сезон, статус, направление, источник, период подачи, наличие замечаний, поиск по названию команды и ФИО.

Карточка заявки — основное рабочее место Оргкомитета:

1. Шапка: команда, направление, статус, дата подачи, источник, быстрые действия.
2. Участники: ФИО, дата рождения и возраст на дату закрытия приёма, категория, организация, контакты, отметки согласий (ПДн, распространение, законный представитель).
3. Наставники (до двух).
4. Материалы: тип, файл/ссылка, версия, статус, комментарий проверяющего, кнопка «Оставить замечание» с обязательным сроком досдачи (не более 2 рабочих дней).
5. История: смена статусов, замечания, действия команды, кто из администраторов что сделал.
6. Блок «Проверка требований»: автоматические отметки — возраст в диапазоне, численность, уникальность участника, полнота комплекта, принадлежность к направлению. Красные отметки не блокируют решение, но требуют явного подтверждения.

Массовые операции: принять группу, отправить на доработку, экспорт выборки.

### 2.3. Материалы (`/admin/materials`)

Очередь проверки: все материалы со статусом `uploaded`, сгруппированные по заявке. Возможности: скачать, открыть ссылку, принять, вернуть с замечанием, отметить «содержание заблокировано». Отдельный фильтр «замечания с истекающим сроком».

### 2.4. Команды, участники, наставники

Списки с поиском; карточка команды: состав, статус и история статусов, участие в этапах, результаты, наложенные санкции. Действия: перевести на следующий этап, дисквалифицировать (с обязательной причиной и записью в журнал), восстановить.

### 2.5. Эксперты, комиссии, Жюри (`/admin/experts`)

Справочник: ФИО, организация, должность, роль (`commission` / `jury` / `expert`), этап, активность. Возможность выдать доступ эксперта к внесению оценок (логин или разовая ссылка) и отозвать его.

### 2.6. Критерии (`/admin/criteria`)

Таблица критериев по трём этапам с максимальными баллами. Редактирование запрещено после публикации первой оценки этапа — изменение критериев в середине оценки недопустимо.

### 2.7. Оценки (`/admin/evaluations`)

Матрица «команда × эксперт» с прогрессом заполнения. Контроль: не менее трёх оценок на инициативу; расхождение сумм более 20 баллов выделяется и требует дополнительной оценки председателя. Возможность заявить конфликт интересов (`is_conflicted`) — такая оценка исключается из подсчёта.

### 2.8. Рейтинги и протоколы (`/admin/rankings`)

1. Кнопка «Рассчитать рейтинг» — черновик: таблица с итоговыми баллами, местами и пометками о равенстве.
2. Проверка правил: среднее с округлением до сотых, разрешение равенства по правилам этапа, наличие всех обязательных оценок.
3. Кнопка «Опубликовать» — загружается PDF протокола, рейтинг становится видимым на сайте, запускается срок апелляций (для этапов, где он предусмотрен).
4. Кнопка «Снять с публикации» — только роль `admin`, с причиной и записью в журнал.

### 2.9. Апелляции (`/admin/appeals`)

Список с фильтром по сроку (в пределах 2 рабочих дней / просроченные / рассмотренные). Карточка: этап, команда, предмет, текст, приложенный скан, решение (удовлетворить / частично / отказать), обоснование, приложенный протокол. Контроль срока рассмотрения — 5 рабочих дней.

### 2.10. Мастер-классы (`/admin/masterclasses`)

CRUD. Поля: заголовок, спикер и должность, дата и время, описание, статус (анонс / прошедший / отменён), **ссылка на запись** или загруженный видеофайл, обложка, публикация. Проверка: прошедший мастер-класс нельзя опубликовать без записи.

### 2.11. Партнёры (`/admin/partners`)

Название, ссылка, логотип, тип (генеральный / спонсор / информационный / площадка), описание, порядок сортировки, публикация. Отдельно отображается предупреждение, если у партнёра нет логотипа.

### 2.12. Новости и видео (`/admin/news`)

Список материалов типа `news` и `video`, публикация, обложка, привязка к сезону. Для видео — ссылка (ВК) с проверкой домена.

### 2.13. Документы (`/admin/documents`)

Юридические документы и Положение: тип, заголовок, версия, дата редакции, PDF, обязательность акцепта при подаче заявки. История версий: прежняя версия не удаляется, а помечается архивной — это нужно для доказательства, с какой редакцией соглашался участник.

### 2.14. Победители (`/admin/winners`)

По годам и номинациям: команда, участники, фото, название проекта, описание, публикация. Блок используется для страницы «Победители» и раздела «История конкурса».

### 2.15. Обращения (`/admin/leads`)

Входящие с публичной формы и из кабинета («дедлайн пропущен»). Статусы: новое, в работе, отвечено, архив. Ответ отправляется из интерфейса (шаблоны писем), результат фиксируется.

### 2.16. Настройки (`/admin/settings`)

Сроки сезона, контакты Оргкомитета, тексты писем, включатели функций (приём заявок, публикация результатов), реквизиты оператора для бланков согласий, контакты Оргкомитета. Каждое изменение — с ревизией и автором.

### 2.17. Пользователи и журнал (`/admin/users`, `/admin/audit`)

Только роль `admin`. Пользователи: создание, смена роли, блокировка, сброс пароля. Журнал: фильтры по пользователю, действию, сущности и периоду; экспорт.

## 3. UX-правила админки

1. **Никаких «мёртвых» кнопок.** Недоступное действие либо скрыто с объяснением, либо неактивно с подсказкой причины.
2. **Опасные действия — отделены.** Удаление, дисквалификация и публикация не соседствуют с повседневными кнопками.
3. **Одно действие — один запрос.** Массовые операции показывают предпросмотр: сколько записей затронуто и что именно изменится.
4. **Формулировки — из словаря (раздел 02, п. 12).** Никаких «лидов», «юзеров» и «кампаний».
5. **Ошибка объясняет, что делать.** «Не удалось сохранить: файл больше 25 МБ. Уменьшите размер или загрузите ссылку».
6. **Таблицы не «прыгают».** Фиксированные колонки, сохранение фильтров в адресной строке (ссылка на отфильтрованный список передаётся коллеге).
7. **Доступность.** Полная работа с клавиатуры, фокус виден, контраст по WCAG 2.1 AA.

## 4. Что делать запрещено

1. Показывать ПДн в списках сверх необходимого (в таблице заявок — ФИО капитана и контакт, не даты рождения).
2. Хранить пароли в открытом виде, в том числе «временно».
3. Удалять заявки и материалы физически (кроме исполнения требования субъекта ПДн).
4. Менять критерии и оценки после публикации протокола без снятия с публикации и записи в журнал.
5. Публиковать имена и фото несовершеннолетних без согласия законного представителя.

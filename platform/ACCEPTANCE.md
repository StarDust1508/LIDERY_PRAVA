# Протокол приёмки платформы «Лидеры права – 2027»

**Прогон:** 4 октября 2026 года, локальная среда (macOS, Node.js 25.8, PostgreSQL 16).
**Команда:** `bash platform/scripts/acceptance.sh`
**Результат:** **пройдено 135 проверок, провалов 0**, блокирующих дефектов нет.

Скрипт поднимает **чистую базу**, прогоняет миграции с нуля, запускает API на
отдельном порту и выполняет приёмочные сценарии через HTTP — теми же запросами,
которые делает браузер. Продовые базы скрипт не трогает: при `DB=liders`
отказывается работать.

## 3. Дефекты, найденные приёмкой и исправленные

| Дефект | Как проявлялся | Исправление |
|---|---|---|
| **Флаг дополнительной оценки не снимался** | После расхождения > 20 баллов и внесения оценки председателя `rankings.needs_chair_review` оставался `true`: команда навсегда помечена как «требуется доп. оценка», хотя оценка уже есть | Флаг теперь означает «оценка председателя ещё нужна»: при наличии `is_chair_extra` он снимается, а балл председателя учитывается в среднем (п. 7.7; ТЗ 04, п. 3.4.3) |
| **Протокол публиковался при неснятом флаге** | ТЗ требует «итог не публикуется до внесения дополнительной оценки председателя», но `POST /rankings/publish` публиковал всё | Публикация отвечает `409` и перечисляет команды, по которым ждёт оценку председателя |
| **Ссылки на зарубежные облака принимались** | С2, шаг 4: законопроект можно было приложить ссылкой на Google Drive | Добавлен перечень российских сервисов (п. 14.4 Положения): ВКонтакте, Яндекс.Диск, Облако Mail.ru, Rutube, Дзен, Одноклассники; отказ объясняет причину |

Дефекты в скрипте приёмки (два `-o` у curl, лишний аргумент, `UPDATE` одной
строки вместо всех) исправлены там же — они не касались платформы.

## 4. Некритические замечания

1. **Общий пароль из окружения остаётся вторым входом.** Он даёт роль администратора без учётной записи: пока он задан, общий пароль нужно менять по регламенту (ТЗ 11, п. 45), а имена вошедших под ним в журнале различить нельзя — только `env:owner`. Постоянные сотрудники заводятся в разделе «Пользователи».
2. **Два уровня защиты входа**: лимит 5 запросов в минуту срабатывает раньше, чем блокировка после 10 неудачных попыток (`LF_MAX`). Поведение безопасное, но `LF_MAX` фактически недостижим — стоит либо поднять лимит запросов, либо убрать второй счётчик.
3. **`lib/signed-links.ts` не используется**: механизм краткосрочных ссылок на приватные файлы реализован, но выдать такую ссылку нечем — администратор открывает файл по сессии. Либо добавить маршрут выдачи, либо убрать модуль.
4. **Проверка интерфейса в браузере** не выполнена: окружение разработки не даёт запустить браузер (Chrome падает, crashpad не пишет вне рабочего каталога). Интерфейс проверен типами, сборкой и сценариями через HTTP; визуальная приёмка — за Оргкомитетом.

## 6. Как повторить

```bash
bash platform/scripts/acceptance.sh                     # чистая база liders_acceptance, порт 3005
DB=liders_acc2 PORT=3006 bash platform/scripts/acceptance.sh
KEEP_DB=1 bash platform/scripts/acceptance.sh           # оставить базу для разбора
```

Скрипт печатает список пройденных и проваленных проверок, перечень пунктов вне
объёма и завершает работу с кодом, равным числу провалов (0 — приёмка пройдена).

## 7. Роли и доступы (пакет 8)

Раздел «Пользователи» и разграничение прав реализованы по ТЗ 07, п. 1.2–1.3 и 2.17.

| Что | Как сделано |
|---|---|
| Хранение | Таблица `users`: `role` (`admin`/`operator`), `is_active`, `auth_version`, `password_hash` (bcrypt, cost 12), `must_change_password`, `created_by`, `blocked_at`, `blocked_reason` |
| Роли | `admin` — всё; `operator` — заявки, материалы, обращения, мастер-классы, новости, документы. Эксперты, справочники, настройки, публикация протоколов и выгрузка ПДн закрыты middleware `requireAdminRole('admin')`, справочники — через `requireAdminForWrites` (читать можно, менять нельзя) |
| Управление | `GET/POST /api/admin/users`, `PATCH /api/admin/users/:id`, `POST /api/admin/users/:id/password`, `POST /api/admin/users/:id/revoke-sessions` |
| Сеанс | 12 часов (`ADMIN_SESSION_TTL_HOURS`), выход после 60 минут бездействия (`ADMIN_IDLE_MINUTES`); отметки активности — в `admin_session_activity` (только SHA-256 токена); интерфейс предупреждает за 5 минут до выхода |
| Гасятся сразу | Блокировка, сброс пароля и «завершить все сеансы» увеличивают `auth_version` — выданные токены перестают работать немедленно |
| Ограничения-предохранители | Нельзя заблокировать или понизить себя; в системе должен остаться хотя бы один действующий администратор среди учётных записей |
| Журнал | Все действия с пользователями и входы по учётным записям пишутся с автором и учётной записью; пароли в журнал не попадают |
